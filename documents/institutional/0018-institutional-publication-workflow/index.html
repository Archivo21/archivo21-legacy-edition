1. Purpose

This workflow moves an Archivo 21 document from preserved source material to an authorised canonical record and readable public webpage without confusing drafting, adoption, storage and publication.

This text is a transparent reconstruction. The internal session record confirms that an Institutional Publication Workflow was prepared and reviewed, but the exact earlier file was not found. This candidate preserves the evidenced requirements without pretending to reproduce lost wording.

2. Preconditions

Before publication:

  1. identify the source files and competing versions;
  2. confirm the responsible repository and canonical path;
  3. classify lifecycle status separately from publication state;
  4. check rights, privacy, safeguarding and access restrictions;
  5. apply #0017 proportionately;
  6. enter the document in #0022;
  7. identify the exact pre-change state of every affected repository; and
  8. preserve a complete recoverable checkpoint for at least 28 days.

An internal session or daily decision record does not become public merely because it supplied evidence for a public document.

3. Version reconciliation

Where more than one version exists:

  • calculate and record integrity hashes;
  • determine whether copies are identical, divergent, superseded, defective or complementary;
  • compare substantive differences rather than filenames alone;
  • select one current canonical text;
  • retain materially different earlier versions;
  • record the disposition in #0023 or a successor reconciliation record.

4. Canonical preparation

The canonical Markdown file should:

  • use its permanent institutional identifier;
  • carry the compact metadata required by #0017;
  • preserve attribution and provenance;
  • link related records;
  • state uncertainty where chronology or authority is incomplete;
  • avoid rewriting externally authored source material merely for house style.

Where a source cannot or should not be edited, use a wrapper record.

5. Public representation

For each public or public-draft document:

  1. generate a readable HTML page from the canonical Markdown;
  2. render headings, lists, tables, code and quotations as formatted content;
  3. use an institutional URL under /documents/institutional/;
  4. link to the canonical repository source from the webpage;
  5. ensure every internal website destination is another webpage;
  6. provide context for superseded or draft material;
  7. keep project records visibly subordinate to the institution on the Archivo 21 site.

The website is a publication layer, not a second canonical document repository.

6. Review gate

Before a publication commit, the human institutional authority should receive:

  • the proposed document register;
  • version-selection decisions;
  • a repository-boundary summary;
  • the full diff for every affected repository;
  • link and rendering results;
  • unresolved choices and withheld internal material;
  • the exact candidate commit identifiers.

No push should occur until that review authorises it.

7. Commit and publication

After approval:

  1. recheck remote heads against the recorded baselines;
  2. create or verify remote recovery references;
  3. publish by normal non-forced fast-forward;
  4. verify repository heads and website deployment;
  5. test public routes and canonical-source links;
  6. record the resulting commits and deployment result;
  7. retain pre-change recovery material for at least 28 days.

8. Failure handling

If a baseline changes, a link cannot be resolved, a source version remains ambiguous, or a public/private decision is missing, stop the affected publication. Preserve the candidate and report the blocker rather than guessing or force-pushing.
