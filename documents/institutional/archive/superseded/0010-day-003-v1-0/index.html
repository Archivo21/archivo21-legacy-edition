Purpose

Day 001 established the project.

Day 002 established and hardened the public face.

Day 003 should establish the operating spine of the institution while returning visible energy to the flagship research programme.

The day should not become an excuse to produce endless governance about governance. Its purpose is to reduce uncertainty, clarify where institutional records belong, preserve the first continuity incident, establish a durable maintenance workflow, and then use that stronger structure to advance EXP001.

The governing test for Day 003 is therefore two-part:

  1. Does this strengthen Archivo 21 as an institution?
  2. Does this make preservation or research easier for ANHQV-TS2?

Work that satisfies neither test should not consume the day.

Goal 2 — Define institutional boundaries before adding more institutional files

Objective

Prevent Archivo 21’s institution-wide records from accumulating indefinitely inside either the ANHQV-TS2 research repository or the public website repository without a deliberate rule.

Problem

The current repositories have distinct intended roles:

  • anhqv-ts2-preservation-project is the canonical research and reconstruction repository for the flagship programme;
  • archivo21.github.io is the public institutional front door, not a second evidence repository.

As Archivo 21 produces general standards, continuity records, governance and maintenance procedures, a canonical home for those records must be chosen.

Tasks

  • [ ]Inventory current institution-wide documents stored in ANHQV-TS2.
  • [ ]Inventory current institution-wide documents stored in the website repository.
  • [ ]Classify each as:
    • project-specific;
    • institution-wide;
    • website-operational;
    • historical or archival;
    • provisional.
  • [ ]Identify documents that currently serve two roles.
  • [ ]Decide between the following models:
    1. retain institution-wide records in a clearly bounded area of ANHQV-TS2 for now;
    2. create a dedicated institutional-records repository;
    3. adopt another documented arrangement.
  • [ ]Do not move files during the audit unless a move is separately authorised and documented.
  • [ ]Produce a one-page repository-boundary decision.
  • [ ]Define which repository is canonical for each record class.
  • [ ]Define how the website links to canonical records without duplicating them.

Decision principle

Archivo 21 may become the enduring institution, but ANHQV-TS2 must not be reduced to a mere example or displaced by administrative expansion.

The institution is the supporting structure. The flagship research programme is where that structure proves useful.

Goal 3 — Establish the documentary lifecycle

Objective

Give every substantial document a visible place in its lifecycle.

Proposed lifecycle

Idea
  ↓
Proposal
  ↓
Discussion
  ↓
Experiment or investigation
  ↓
Evidence
  ↓
Decision
  ↓
Publication
  ↓
Review
  ↓
Supersession or archive

Not every document must pass through every stage. The lifecycle is a map, not a bureaucratic obstacle course.

Tasks

  • [ ]Review the lifecycle against existing project practice.
  • [ ]Define the minimum statuses used across institutional documents.
  • [ ]Distinguish document status from evidence certainty.
  • [ ]Proposed document statuses:
    • Draft;
    • Proposed;
    • Under review;
    • Adopted;
    • Active;
    • Superseded;
    • Archived.
  • [ ]Preserve the existing evidence categories:
    • Observation;
    • Inference;
    • Hypothesis;
    • Speculation;
    • Conclusion.
  • [ ]Define who may change a document’s status.
  • [ ]Define when a superseded document remains publicly discoverable.
  • [ ]Add a compact metadata pattern that does not make ordinary Markdown unpleasant to maintain.
  • [ ]Test the pattern on CONT-001, one governance document and one experiment record.
  • [ ]Record exceptions rather than forcing unsuitable documents into the pattern.

Recommended order

  1. Review and adopt CONT-001.
  2. Make the repository-boundary decision.
  3. Adopt the documentary lifecycle and status vocabulary.
  4. Establish the Maintenance Backlog.
  5. Close contact routing and manual Day 002 checks.
  6. Define and test the moderated pull-request workflow.
  7. Complete or materially advance the experiment-media inventory.
  8. Select the next public-safe EXP001 evidence unit.

This order preserves today’s continuity event before its details blur, prevents institutional records from drifting into the wrong repository, closes operational gaps, and then returns the strengthened system to the research that justified it.

Scope restraints

Day 003 should not:

  • redesign the website again unless a defect is found;
  • create a new repository before the repository-boundary decision;
  • move canonical files merely to make the tree look cleaner;
  • activate contact addresses before end-to-end testing;
  • treat EXTERNAL-AI-001 as identical to either institutional participant A21-AI-001 or ANHQV-TS2 project contributor ANHQV-AI-001;
  • grant contributor or institutional status through implication;
  • add broad standards with no tested use;
  • let governance consume the entire day;
  • claim that a live service has been verified when only repository records were inspected.

Definition of done

Day 003 is complete when:

  • CONT-001 and its primary source are preserved with a reconciliation outcome;
  • the provisional identity and attribution status of EXTERNAL-AI-001 are explicit;
  • Archivo 21 has chosen or formally deferred a canonical home for institution-wide records;
  • a documentary lifecycle and minimum status vocabulary have been tested on real files;
  • Maintenance Backlog.md has been adopted as a living task reservoir;
  • every unresolved Day 002 infrastructure item is either verified, completed, or explicitly carried forward;
  • the contact-routing activation state remains honest;
  • the moderated pull-request workflow has a documented next action;
  • and the EXP001/media-custody work has advanced through a concrete, preserved output.

End-of-day record

At the end of Day 003, record:

  • documents adopted;
  • decisions made;
  • tasks completed;
  • tasks moved to the Maintenance Backlog;
  • unresolved verification items;
  • EXP001 progress;
  • any material disagreement between contributors;
